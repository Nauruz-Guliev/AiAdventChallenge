# AI Advent Challenge

Небольшие проекты для изучения LLM API.

## Дни

- [`day1`](./day1) — веб-чат с OpenCode-совместимым LLM API.
- [`day2`](./day2) — наглядное сравнение обычного ответа и ответа с ограничениями формата, длины и завершения.
- [`day3`](./day3) — сравнение четырёх способов рассуждения на одной логической задаче с автоматической проверкой точности.
- [`day4`](./day4) — сравнение одного творческого запроса при temperature `0`, `0.7` и `1.2`.
- [`day5`](./day5) — сравнение одного аналитического запроса на слабой, средней и сильной модели с замером времени, токенов и reference-стоимости.
- [`day6`](./day6) — первый отдельный Python-агент с FastAPI, DeepSeek API и React-интерфейсом, показывающим поток запроса.
- [`day7`](./day7) — сохранение контекста: история чатов в JSON переживает перезапуск, интерфейс показывает список чатов.
- [`day8`](./day8) — подсчёт токенов и лимит контекста: запрос/история/ответ, накопительная стоимость и переполнение бюджета.
- [`day9`](./day9) — управление контекстом: rolling-summary вместо старой части истории, тумблер сжатия и сравнение качества/токенов.
- [`day10`](./day10) — стратегии контекста: sliding window, sticky facts и ветвление с автосравнением на одном сценарии.
- [`day11`](./day11) — модель памяти ассистента: краткосрочная, рабочая и долговременная память хранятся раздельно.
- [`day12`](./day12) — персонализация ассистента: структурированный профиль (стиль, формат, ограничения) подключается к каждому запросу.
- [`day13`](./day13) — состояние задачи: конечный автомат `planning → execution → validation → done`, пауза и продолжение без повторных объяснений.
- [`day14`](./day14) — инварианты ассистента: ограничения хранятся отдельно от диалога, учитываются в каждом ответе и блокируют решения, которые их нарушают.
- [`day15`](./day15) — контролируемые переходы состояний: явная таблица переходов `planning → approval → execution → validation → done`, ассистент не может перепрыгнуть этап.
- [`day16`](./day16) — подключение MCP: минимальный MCP-сервер с инструментами и клиент-пример.
- [`day17`](./day17) — первый инструмент MCP: погода (`get_weather`, `get_forecast`).
- [`day18`](./day18) — планировщик и фоновые задачи: отложенное и периодическое выполнение.
- [`day19`](./day19) — композиция MCP-инструментов: цепочка складывается внутри одного сервера.
- [`day20`](./day20) — оркестрация MCP: сервер-оркестратор ходит в несколько серверов и возвращает `trace`.
- [`day21`](./day21) — индексация KMP-документов: chunking (2 стратегии), эмбеддинги, локальный JSON-индекс и сравнение стратегий.
- [`day22`](./day22) — первый RAG-запрос: вопрос → поиск чанков → контекст + вопрос → LLM; два режима (без RAG / с RAG), 10 контрольных вопросов и сравнение качества.
- [`day23`](./day23) — реранкинг и фильтрация: фильтр по similarity-порогу, heuristic-реранкинг и query rewrite; пять режимов и сравнение качества.
- [`day24`](./day24) — цитаты, источники и анти-галлюцинации: дословные цитаты через LCS и правило «не знаю» по порогу релевантности; три режима и сравнение качества.
- [`day25`](./day25) — мини-чат с RAG и памятью задачи: история на диске, источники в каждом ответе и «память задачи» (цель/уточнения/ограничения), обновляемая LLM; проверка на 2 сценариях.

Каждый день является отдельным проектом и содержит собственную инструкцию по запуску.
