# День 8: подсчёт токенов и лимит контекста

Самостоятельное продолжение `day7`. Агент считает токены текущего запроса, всей истории диалога и ответа модели, показывает накопительную стоимость и честно ломается на лимите контекста.

`day6` и `day7` не изменяются.

## Что изучаем

Языковые модели не помнят ничего: каждый запрос пересылает всю историю заново. Значит, диалог из десяти ходов платит за первые девять сообщений десять раз — токены и стоимость растут быстрее, чем длина нового вопроса.

Три вопроса, на которые отвечает этот день:

1. сколько токенов в текущем запросе, в истории и в ответе модели;
2. как это накапливается и во что обходится по мере диалога;
3. что ломается, когда диалог превышает лимит контекста.

## Два источника чисел

- **Локальная оценка до отправки** (`tiktoken`, `cl100k_base`): только так можно разделить «текущий запрос» и «историю» и предсказать переполнение *до* запроса. У DeepSeek свой токенизатор, поэтому это оценка, а не биллинг.
- **Точный `usage` из ответа API**: `prompt_tokens`, `completion_tokens`, `total_tokens`. Сохраняется в JSON вместе с каждым assistant-сообщением, поэтому накопленные токены и стоимость переживают перезапуск.

## Бюджет контекста

Реальный лимит `deepseek-chat` сегодня — **1M токенов** (легаси-имя обслуживает модель `deepseek-flash` / DeepSeek-V4.1-Flash). Переполнять его по-настоящему из UI смысла нет: это сотни долларов на запросы. Поэтому приложение использует настраиваемый бюджет:

```env
CONTEXT_LIMIT_TOKENS=8000
INPUT_PRICE_PER_MILLION=0.30
OUTPUT_PRICE_PER_MILLION=1.20
```

Цены — worst-case пиковые для `deepseek-flash` (cache miss), источника: официальная документация DeepSeek. При `≥ 80%` бюджета UI предупреждает, при превышении Agent отклоняет запрос **до обращения к API**: сообщение не отправляется и не сохраняется.

## Что происходит при переполнении

- `POST /api/chats/{id}/messages` → `HTTP 413` с телом `{detail, estimated_tokens, context_limit}`;
- exchange не попадает в `data/chats.json`;
- UI показывает баннер и блокирует ввод — продолжить диалог нельзя, только новый чат.

Настоящий ответ DeepSeek при переполнении реального лимита — `HTTP 400` с кодом `context_length_exceeded`. Gateway маппит и его в ту же ошибку.

## Демонстрация: три сценария на живом API

Все числа ниже — фактические результаты прогонов в этом приложении (бюджет 8000 токенов).

### Сценарий A: короткий диалог

Два коротких сообщения:

| ход | оценка запроса | оценка истории | API prompt | API completion | Σ диалога | стоимость |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 13 | 50 | 57 | 26 | 83 | $0.000048 |
| 2 | 22 | 105 | 98 | 38 | 219 | $0.000123 |

Стоимость почти целиком из ответов: история ещё копеечная.

### Сценарий B: длинный диалог

Каждое сообщение — ~1200 токенов (оценка), ответы ~900. Симуляция длинного диалога (кнопка в UI):

| ход | оценка истории | API prompt | API completion | Σ диалога | стоимость | остаток бюджета |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 50 | 816 | 902 | 1 718 | $0.001327 | 5564 |
| 2 | 2 436 | 2 487 | 952 | 5 157 | $0.003216 | 3083 |
| 3 | 4 917 | 4 208 | 899 | 10 264 | $0.005557 | 691 (warning ≥80%) |

Рост почти квадратичный: `API prompt` каждого хода содержит всю предыдущую историю, а не только новый вопрос. Прирост за ход — ~800, затем ~1700, ~2500 токенов.

### Сценарий C: переполнение

Четвёртый ход той же симуляции:

```text
HTTP 413
Диалог превысил лимит контекста (8477 из 8000 токенов).
Сообщение не отправлено и не сохранено. Начните новый чат.
```

Проверка после отказа: в истории чата по-прежнему 3 сохранённых exchange — сломанный запрос не оставил следов. Диалог «заморожен»: продолжить его нельзя, работает только новый чат.

Наблюдение из прогонов: оценка tiktoken для русского текста здесь консервативна (запрос на ~1170 токенов по оценке API-провайдер посчитал в ~770 реальных токенов истории). Оценка — для предсказания, биллинг — только по `usage`.

## Запуск backend

```bash

python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

Создай `day8/backend/.env` по образцу `.env.example` и укажи ключ DeepSeek:

```env

DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-chat
CONTEXT_LIMIT_TOKENS=8000
```

```bash
uvicorn app.main:app --reload
```

```bash
cd day8/frontend
npm install
npm run dev
```

Открой `http://localhost:5173`. Если `day7` ещё запущен на тех же портах — сначала останови его.

## API

- `POST /api/chats` — создать чат;
- `GET /api/chats` — список чатов;
- `GET /api/chats/{id}` — история + `usage` каждого assistant-сообщения + `dialog_usage`;
- `DELETE /api/chats/{id}` — удалить чат;
- `POST /api/chats/{id}/messages` — ответ + полное поле `usage` (оценки, API-числа, накопленное, остаток бюджета); при переполнении — `413`.

## Структура

- `backend/app/domain/models.py` — `TokenUsage`, `UsageConfig`, `DialogUsage`, `UsageReport`, `ContextLimitExceeded`;
- `backend/app/infrastructure/token_counter.py` — локальная оценка tiktoken;
- `backend/app/application/usage.py` — накопительная стоимость и заполнение бюджета;
- `backend/app/application/agent.py` — pre-check бюджета до отправки и сборка `UsageReport`;
- `backend/app/infrastructure/deepseek_gateway.py` — точный `usage` из API и маппинг `400 context_length_exceeded`;
- `frontend/src/components/UsagePanel.jsx` — прогресс-бар бюджета, стоимость, кнопка симуляции.

## Ограничения

- Локальные числа — оценка `cl100k_base`, они расходятся с токенизатором DeepSeek (в этих прогонах — в консервативную сторону).
- Стоимость считается worst-case (пик, cache miss); DeepSeek дешевле при попадании в кэш.
- Автообрезки или суммаризации истории нет — это решение следующего уровня, в этот день мы только показываем поломку.
- Бюджет `8000` — учебный; реальный лимит модели — 1M токенов, измени `CONTEXT_LIMIT_TOKENS`, если хочешь другой.
