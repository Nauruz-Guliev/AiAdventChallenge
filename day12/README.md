# День 12: персонализация ассистента

Самостоятельное продолжение `day11`. Поверх модели памяти добавлен профиль
пользователя: стиль, формат и ограничения. Профиль хранится отдельно от памяти
и подключается к **каждому** запросу автоматически.

`day6`–`day11` не изменяются.

## Что изучаем

День 11 отвечал «что ассистент помнит». День 12 отвечает «как ассистент отвечает
именно этому пользователю». Профиль — это отдельный слой, который управляет тоном,
объёмом, форматом и ограничениями ответа, не смешиваясь с фактами о пользователе.

| слой | что хранит | где лежит |
| --- | --- | --- |
| профиль | личность и предпочтения: тон, объём, формат, ограничения | `data/profiles.json` |
| долговременная | факты: профиль, решения, знания | `data/long_term.json` |
| рабочая | карточка текущей задачи | `data/chats/<id>.json` |
| краткосрочная | история текущего диалога | `data/chats/<id>.json` |

**Профиль = как отвечать. Долговременная `profile` = что известно.** Профиль
вставляется в промпт первым и задаёт стиль; факты памяти остаются содержанием.

## Поля профиля

- личность: `title` (название профиля), `name` (имя), `role` (роль), `language`;
- стиль: `tone` — деловой / дружелюбный / нейтральный;
- объём: `length` — коротко / средне / подробно;
- формат: `structure` — текст / списки / markdown;
- ограничения: список правил, например «без эмодзи», «без воды».

## Пресеты и активный профиль

При первом запуске заводятся четыре профиля:

| профиль | тон | объём | формат | ограничения |
| --- | --- | --- | --- | --- |
| Нейтральный (без персонализации) | нейтральный | средний | текст | — |
| Деловой | деловой | средний | markdown | без эмодзи; без воды |
| Коротко и по делу | нейтральный | короткий | списки | без вступлений и итогов; не больше трёх пунктов |
| Наставник | дружелюбный | подробный | markdown | объясняй термины простыми словами; приводи пример |

Активный по умолчанию — «Деловой». Переключается чипом в панели «Профиль».
«Нейтральный» отключает персонализацию: блок профиля не добавляется, токенов не
тратит.

## Как профиль влияет на ответы

Промпт собирается из четырёх слоёв:

```
[system]
## Профиль пользователя        # пропускается, если профиль нейтральный
## Долговременная память
## Рабочая память
<история диалога>
```

Под ответом в «Что учтено в ответе» появляется строка «профиль», а в мета-строке —
токены профиля (`профиль N`). Так видно, что ассистент учёл профиль **без явной
просьбы** в сообщении.

## Ручной ритуал проверки

1. Активен «Деловой». Спросите «Объясни, что такое API» — ответ сухой,
   структурированный, без эмодзи.
2. Переключите «Коротко и по делу», тот же вопрос — короткий список без вступлений.
3. Переключите «Наставник» — дружелюбно, подробно, с примером.
4. Откройте «Что учтено в ответе» — строка «профиль» присутствует (учёт
   автоматический).
5. В «Коротко и по делу» добавьте ограничение «без эмодзи» и сохраните — ответ без
   эмодзи.
6. **Новый чат** — профиль сохраняется: он глобальный, не привязан к чату.
7. Переключите «Нейтральный» — строка «профиль» исчезает, токены профиля `0`.

## Запуск

```powershell
# backend (Windows)
cd day12\backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
# .env: DEEPSEEK_API_KEY=... (см. .env.example)
.venv\Scripts\python -m uvicorn app.main:app --reload
```

```powershell
# frontend — во втором терминале
cd day12\frontend
npm install
npm run dev   # http://localhost:5173
```

Если `day11` держит порт 8000/5173 — сначала остановите его.

## API

- `GET /api/profiles` → `{active_id, profiles}`;
- `GET /api/profiles/presets` → шаблоны;
- `GET /api/profile` → активный профиль;
- `POST /api/profiles` · `POST /api/profiles/from-preset {key}`;
- `PUT /api/profiles/{id}` · `DELETE /api/profiles/{id}` (последний удалить нельзя);
- `POST /api/profiles/{id}/activate`;
- остальные эндпоинты — как в `day11`.

## Честные ограничения

- Модель может частично смягчить стиль (особенно «коротко») — гарантии 100% нет.
- Конфликт «профиль ↔ история» не разрешается автоматически: побеждает то, что
  позже в промпте.
- Профиль глобальный, на одного пользователя (мультиюзера нет).
- Авто-обучения профиля из диалога нет — только ручная правка.
- Профиль тратит токены в каждом запросе (видно в мета-строке).

## Структура

- `app/domain/models.py` — `UserProfile`, `ProfileStore`, `ProfilePreset`, пресеты;
- `app/application/profiles.py` — блок `## Профиль пользователя`, трейс, валидация;
- `app/application/memory.py` — порядок слоёв промпта;
- `app/application/agent.py` — загрузка активного профиля в каждый запрос;
- `app/infrastructure/json_profile_repository.py` — хранилище `profiles.json`;
- `frontend/src/components/ProfilePanel.jsx` — переключатель, форма, пресеты;
- `frontend/src/components/ChatPanel.jsx` — строка «профиль» в трейсе и токены.
