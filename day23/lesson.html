День 23 — Реранкинг и фильтрация

Добавляем к поиску второй этап: фильтр релевантности + heuristic-реранкинг и query rewrite. Сравниваем пять режимов на 10 вопросах.

Идея

Векторный поиск не гарантирует релевантность топа и не уточняет запрос. День 23 встраивает два этапа: до поиска — rewrite вопроса в англоязычный запрос, после поиска — фильтр по порогу и реранкинг по пересечению терминов.

вопрос → [rewrite → запрос] → поиск top-K_pre → фильтр → реранк → top-K_post → LLM

Фильтр и реранкинг

Фильтр

K_pre = 30 → отсечение по cosine-порогу MIN_SIM → K_post = 8. Если отброшено всё — fallback на исходные top-K_post.

Heuristic-реранкинг

final = 0.6·sim + 0.3·lex + 0.1·head, где lex — пересечение терминов запроса с текстом, head — бонус за заголовок/секцию.

Пайплайн

  • query_rewriter.py — LLM-rewrite вопроса в англ. запрос.
  • retrieval.py — cosine-поиск по индексу Дня 21.
  • heuristic_reranker.py — фильтр по порогу + реранкинг.
  • agent.py — 5 режимов, сборка контекста, вызов DeepSeek.
  • evaluator.py — LLM-судья и сравнение режимов.

Результаты

РежимБаллПокрытие
Без RAG0.98—
RAG (baseline)0.830.80
RAG + фильтр/реранк0.810.90

Разбор. Фильтр + реранкинг поднимают покрытие источников с 0.80 до 0.90 — поиск находит нужные доки точнее. Средний балл почти не меняется: судья оценивает ответ, а ответ и так силён. Rewrite в одиночку чуть проседает по баллу, но поднимает профильный документ в топ. Вывод — второй этап улучшает precision поиска и надёжность ссылок.
