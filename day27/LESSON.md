# День 27 — Интеграция локальной LLM в Telegram-бота (урок)

## Идея

День 26 мы научились запускать локальную модель и общаться с ней вручную (CLI/HTTP/страница).
День 27 — встроить её в **реальное приложение**: Telegram-бота. Пользователь пишет боту,
бот обращается к локальной модели и показывает ответ. Никаких облачных LLM.

## Почему Telegram и почему long polling

У Telegram-бота два способа получать сообщения:

- **webhook** — Telegram стучится на твой публичный HTTPS-URL. Нужен сервер, домен, сертификат.
- **long polling** — бот сам опрашивает Telegram (`getUpdates`) длинными запросами.
  Публичный URL **не нужен**.

Для локальной модели это идеальный вариант: всё крутится на домашнем ПК, наружу торчит только
исходящее соединение к Telegram. Никаких портов, доменов и сертификатов.

## Архитектура: ядро не знает про Telegram

Ключевая мысль — **разделить слои**:

```
порт LLMClient  ← ядро (application) зависит только от него
   ↑ реализует
OllamaClient (infrastructure) → httpx → /api/chat
```

Ядро (`ChatService`) умеет: собрать запрос (system + история + новый ход), получить
стрим ответа, посчитать статистику, обрезать контекст, сохранить историю. Оно **не знает**,
что это Telegram, и не знает, что под капотом httpx. Поэтому его можно тестировать офлайн
через `FakeLLMClient`, а Telegram-слой — отдельно.

Так же и рендер: `TelegramMessageStreamer` принимает функции `send`/`edit` как параметры,
поэтому его поведение (троттлинг правок, разбивка длинного ответа) тестируется без реального
бота.

## Стриминг в Telegram

Ollama умеет отдавать ответ потоком (`"stream": true`) — NDJSON, по строке на кусок:
`message.thinking` (размышления) и `message.content` (ответ). Telegram, в отличие от браузера,
не умеет «дописывать» текст в сообщение построчно — но умеет **редактировать** сообщение.

Приём: отправляем одно сообщение и **обновляем его** (`edit_message_text`) по мере поступления
кусков, но не чаще, чем раз в ~1.2 секунды (иначе Telegram отдаёт 429 и ругается
«message is not modified»). Получается эффект «модель печатает».

Нюансы:
- ответ длиннее 4096 символов → разбиваем и «переливаем» хвост в новое сообщение;
- Markdown модели преобразуем в безопасный Telegram-HTML (экранируем `<`, `>`, `&`), а при
  ошибке — отправляем простым текстом;
- у `gemma4:12b` есть «размышления» — их можно показать отдельным сообщением (`/think on`).

## Память диалога

История хранится на диск: `data/chats/<chat_id>.json`. На каждом ходу в модель уходит
`system + последние N ходов + новый вопрос`. История обрезается по числу сообщений и по объёму
символов, чтобы не раздувать контекст. Перезапуск бота историю не теряет.

Для фото в историю пишется плейсхолдер `[фото]`, а не base64-картинка — иначе файл распухнет.

## Vision (описание фото)

Ollama принимает изображение в сообщении: `{"role":"user","content":"...","images":["<base64>"]}`.
Бот скачивает фото из Telegram, кодирует в base64 и отправляет вместе с подписью (или с
дефолтным промптом «Опиши изображение»). У `gemma4:12b` есть capability `vision`.

## Когда модель недоступна

Остановил Ollama — `httpx` кидает ошибку подключения. Мы заворачиваем её в `OllamaUnavailable`
и показываем пользователю дружелюбное «⚠️ локальная модель не отвечает, запусти Ollama». Это
заодно хорошая демонстрация, что модель реально локальная.

## Что пошло в код

- `domain/models.py` — `Role`, `ChatMessage`, `GenerationStats`, `ChatState`.
- `ports/llm.py` — `LLMClient` и события `StreamDelta`/`StreamDone`, `OllamaUnavailable`.
- `infrastructure/ollama_client.py` — async-стрим `/api/chat`, `/api/tags`, `/api/version`.
- `infrastructure/chat_store.py` — JSON-хранилище с атомарной записью.
- `application/chat_service.py` — оркестрация, история, статистика, обрезка.
- `application/formatter.py` — markdown→HTML, разбивка, футер «локально».
- `application/vision.py` — base64 и промпт для фото.
- `presentation/handlers.py` — команды, текст, фото; `streamer.py` — троттлинг правок;
  `middlewares.py` — обработка ошибок; `messages.py` — тексты.
- `main.py` — сборка и запуск (long polling).

## Как воспроизвести

```powershell
# 1. Модель (из Дня 26)
ollama pull gemma4:12b

# 2. Токен бота у @BotFather → в .env
cd day27/backend
copy .env.example .env

# 3. Зависимости и запуск
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m app.main
```

## Тесты (офлайн)

```powershell
.venv\Scripts\python.exe -m pytest -q
```

`FakeLLMClient` подменяет Ollama, `httpx.MockTransport` — сеть. Проверяем: сборку истории,
обрезку, `/reset`, смену модели, статистику, парсинг NDJSON, vision-base64, троттлинг стримера,
разбивку длинных сообщений.
