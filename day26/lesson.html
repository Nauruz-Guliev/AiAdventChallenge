День 26 — Запуск локальной LLM

Модель крутится на вашем компьютере: Ollama + gemma4:12b. Без облака, без API-ключа.

Идея

До сих пор каждый день ходил в облачное LLM API (DeepSeek). День 26 другой: мы запускаем модель у себя на компьютере и общаемся с ней без облака. Это и есть локальная LLM.

Ollama

Ollama — менеджер локальных моделей. Скачивает модели (ollama pull), запускает их и держит HTTP-сервер на http://localhost:11434. Даёт CLI и HTTP API:

# CLI
ollama run gemma4:12b "Привет!"

# HTTP API (то же самое, программно)
POST http://localhost:11434/api/chat
{ "model": "gemma4:12b", "messages": [{"role":"user","content":"Привет!"}] }

Три запроса разной сложности

  • Простой — «Кто ты?» — модель представляется.
  • Средний — «Разница между процессом и потоком» — объяснение.
  • Сложный — «Функция-палиндром + сложность» — код и O(n)/O(n).

Почему нет MCP и веб-поиска

Базовая LLM — это «текст → текст». MCP и поиск — возможности обвязки-агента, а не самой модели:

  • MCP — протокол, по которому агент подключает инструменты.
  • веб-поиск — HTTP-инструмент, который агент вызывает.

ollama run или fetch('/api/chat') общаются с «голой» моделью, поэтому инструментов нет — это нормально и не слабость модели. Даже GPT-4 без обвязки не ищет в интернете.

Чтобы локальная модель пользовалась инструментами, её подключают как провайдера к агенту (OpenCode, Claude Code и т.п.): агент даёт MCP и поиск, модель — генерацию текста.

Запуск

ollama pull gemma4:12b                 # скачать модель (один раз)
ollama run gemma4:12b "Привет!"        # CLI

cd day26
.\demo.ps1                             # 3 запроса через HTTP API

cd day26/chat
.\serve.ps1                            # чат на http://localhost:8000
