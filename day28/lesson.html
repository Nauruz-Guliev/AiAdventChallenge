День 28 — Telegram-бот с RAG на локальной LLM

Разбор «сделай сам»: локальный retrieval + локальная генерация, сравнение с облаком.

Идея

Соединяем два готовых куска: RAG Недели 6 (индекс KMP + эмбеддинги) и локальную модель (Дни 26–27). Retrieval и генерация работают на твоём компьютере, облако — только как «вторая модель» для сравнения и как судья.

Конвейер

вопрос → embed (локально)
       → top-30 → реранк → фильтр(≥0.35) → top-6
       → gating: релевантность ≥0.60 иначе «не нашёл»
       → prompt: system + история + контекст[n] + вопрос
       → gemma4:12b (Ollama, стриминг) → ответ
       → «📚 Источники» [n] source :: section (score) [+ цитаты]

Шаги, чтобы повторить

  1. Собери индекс Дня 21 (если нет): cd day21 → .venv\Scripts\python.exe pipeline.py --strategy both --embedder sentence.
  2. Установи зависимости Дня 28: cd day28/backend → python -m venv .venv → .venv\Scripts\python.exe -m pip install -r requirements.txt. При ошибке сертификата добавь --trusted-host pypi.org --trusted-host files.pythonhosted.org.
  3. Скопируй .env.example в .env, впиши TELEGRAM_BOT_TOKEN (тот же, что в Дне 27) и DEEPSEEK_API_KEY (для сравнения).
  4. Останови бота Дня 27 — токен один: .\stop_bot.ps1.
  5. Запусти: .\run_bot.ps1. В логе — «Индекс: … (4817 чанков)», «Ollama: OK», «Bot started. Polling…».
  6. В Telegram: /start → задай вопрос → увидишь ответ со стримингом и источники.
  7. Нажми ⚖️ Сравнить или отправь /compare <вопрос> — рядом локальный и облачный ответ с временем.
  8. Отправь /eval — прогресс и таблица «качество / скорость / стабильность».
  9. /norag — ответ без поиска (контраст «с RAG / без RAG»).

Почему судья «слепой»

Судье дают только вопрос, эталон и ответ — без подписи модели. Иначе в сравнении «локальная против облачной» судья (сам облачный) мог бы подыгрывать своим. Ответ судьи — JSON {"score": 0..1, "reason": "…"}.

Метрики

  • Качество — средняя оценка судьи (0…1) и её разброс σ.
  • Скорость — средняя латентность (мс); для локальной — ещё tok/s из Ollama.
  • Стабильность — σ балла и σ латентности по прогонам + доля ошибок.
3 прогона на вопрос нужны именно для оценки стабильности: один прогон о ней ничего не говорит.

Если что-то не так

Telegram не отвечает — сеть может блокировать Telegram: задай TELEGRAM_API_IP=149.154.167.220 в .env.
«нет чанков» / IndexNotFound — не собран индекс Дня 21 (INDEX_PATH).
Долгий первый ответ — грузится модель эмбеддингов (~470 МБ) и/или gemma в Ollama.
Облако «недоступно» — нет DEEPSEEK_API_KEY; локальный режим работает и без него.
