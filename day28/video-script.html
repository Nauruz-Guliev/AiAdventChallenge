День 28 — Telegram-бот с RAG на локальной LLM

Сценарий видео · сухое, без голоса и без титров — только действия на экране

Формат. Немое видео: зритель видит терминал и Telegram. Ниже — ровно то, что делаешь мышью и клавиатурой, по порядку. «Видно» — что получается в кадре само собой. Retrieval и генерация — локальные; облако появляется только на шаге сравнения.
  1. 0:00В терминале: ollama list, затем ollama ps.
    Видно: локальная модель gemma4:12b.
  2. 0:12Показать индекс: открыть day21/index/structure.json (размер) — «база знаний KMP, 4817 чанков».
    Видно: готовый индекс Недели 6.
  3. 0:22Остановить бота Дня 27 (если запущен): cd day27/backend → .\stop_bot.ps1.
    Видно: «Bot is not running» или остановка PID.
  4. 0:32Запустить бота Дня 28: cd day28/backend → .\run_bot.ps1.
    Видно: лог «Индекс: … (4817 чанков)», «Ollama: OK», «Модель: gemma4:12b», «Bot started. Polling…».
  5. 0:50В Telegram отправить /start.
    Видно: «Я — локальный RAG-ассистент по Kotlin Multiplatform» + команды.
  6. 1:00Задать KMP-вопрос: «Как работают expect и actual declarations в Kotlin Multiplatform?».
    Видно: ответ печатается посимвольно и отдельное сообщение «📚 Источники: [1] … (0.7x)» с цитатами и кнопками под ним.
  7. 1:35Второй вопрос по базе: «Как добавить зависимость в commonMain?».
    Видно: снова ответ со стримингом и источники — поиск по индексу работает.
  8. 2:05Нажать кнопку ⚖️ Сравнить.
    Видно: «🖥️ Локально (N мс) …» и «☁️ Облако (N мс) …» — два ответа рядом с временем.
  9. 2:40Нажать 🔄 RAG: выкл, спросить то же самое.
    Видно: ответ без блока источников — контраст «с RAG / без RAG». Вернуть 🔄 RAG: вкл.
  10. 3:10Отправить /eval.
    Видно: сообщение с прогрессом («🧪 Прогон: 4/30…»), затем таблица качество / скорость / стабильность по трём строкам.
  11. 3:40Отправить /status.
    Видно: модель, индекс, эмбеддер, режим, облако.
  12. 3:55Остановить запись.
