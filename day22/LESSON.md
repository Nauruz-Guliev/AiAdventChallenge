# День 22 — Первый RAG-запрос (урок)

## Идея

Обычный ассистент отвечает из «памяти» модели: знания общие и могут быть
устаревшими или неточными. **RAG** (Retrieval-Augmented Generation) добавляет
шаг поиска: сначала находим нужные фрагменты в своей базе, потом просим модель
ответить, опираясь на них.

```
без RAG:  вопрос ──────────────────────────────► LLM ──► ответ
с RAG:    вопрос ─► поиск top-k ─► контекст+вопрос ─► LLM ──► ответ + источники
```

Ключевой тезис: **качество RAG определяется качеством поиска**.

## Компоненты (backend)

- `app/application/agent.py` — `RAGAgent.answer(question, mode)` с режимами
  `no_rag` и `rag`; собирает контекст из найденных чанков и зовёт LLM.
- `app/application/evaluator.py` — прогон контрольных вопросов в обоих режимах,
  LLM-судья (0…1), покрытие источников, сводка.
- `app/infrastructure/retrieval.py` — `JsonRetriever`: грузит индекс Дня 21 и
  делает cosine-поиск через numpy.
- `app/infrastructure/deepseek_gateway.py` — клиент DeepSeek (OpenAI-совместимый).
- `app/infrastructure/fake_llm.py` — детерминированная заглушка для тестов.
- `app/presentation/` — FastAPI: `/api/answer`, `/api/questions`, `/api/eval`.

## Промпты

- **no_rag**: «Ты — ассистент по KMP. Отвечай кратко по своим знаниям.»
- **rag**: «Используй приведённый контекст как основной источник, опирайся на
  факты, в конце перечисли источники. Если контекста не хватает — дополни своими
  знаниями и пометь это.»

Контекст собирается с заголовками источника и секции:

```
[1] kmp-docs/071-...-expect-actual.md :: ... > Rules for expected and actual declarations
<текст чанка>
```

## 10 контрольных вопросов

Для каждого зафиксированы:

- `expectation` — что должно быть в ответе;
- `sources` — подстроки ожидаемых файлов.

Список: `app/data/eval_questions.json`.

## Оценка качества

1. По каждому вопросу — ответ в обоих режимах.
2. **LLM-судья** ставит 0…1 каждому ответу против ожидания.
3. **Покрытие источников** — попали ли ожидаемые файлы в top-k retrieval.

Отчёт: средний балл «без RAG» и «с RAG» + доля вопросов с покрытием источников.

## Результаты (реальный прогон)

| Метрика | Значение |
|---|---|
| Средний балл без RAG | 0.98 |
| Средний балл с RAG | 0.74 |
| Покрытие источников | 0.80 |

**Разбор.** Модель и так хорошо знает KMP, поэтому «без RAG» даёт почти максимум.
RAG выигрывает там, где нужна **конкретика и ссылки на документацию**, но
проигрывает в полноте: чанки по ~120 токенов и англоязычные доки при русском
вопросе не всегда покрывают вопрос целиком. Это и есть урок — усиливать нужно
retrieval (размер/пересечение чанков, кросс-языковой поиск, ре-ранкинг).
