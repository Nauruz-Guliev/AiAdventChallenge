День 25 — Мини-чат с RAG и памятью задачи

Многоходовый чат: история на диске, RAG на каждом вопросе, источники в каждом ответе и память задачи, которая не теряется.

Идея

Дни 22–24 отвечали на один вопрос. Реальный чат — диалог, в котором надо помнить цель, уточнения и ограничения. День 25 собирает мини-чат: история + RAG + источники + память задачи.

Память задачи

{
  "goal": "Настроить минимальный рабочий KMP-проект",
  "clarifications": ["нужны таргеты Android и iOS"],
  "constraints": ["только Kotlin 2.0"],
  "terms": ["expect/actual", "commonMain"]
}
Что хранит

цель, уточнения, ограничения, термины. Цель задаётся при старте сессии и не теряется: если апдейт вернул пустую цель — остаётся старая.

Как обновляется

LLM каждый ход возвращает JSON-память, backend делает merge (union без дублей), не перезаписывая уже зафиксированное.

Цикл одного хода

вопрос → [rewrite с целью] → поиск k_pre → реранк → фильтр k_post
       → промпт = системный + ПАМЯТЬ + ИСТОРИЯ + КОНТЕКСТ(RAG) + вопрос
       → LLM-ответ с [n] → цитаты (LCS) → LLM-апдейт памяти → save

Проверка (2 сценария × 11 сообщений)

passed = все три условия:

  • Источники всегда — у каждого ответа ассистента ≥ 1 источника.
  • Цель не потеряна — итоговая цель непустая и пересекается с начальной.
  • Память накопилась — есть хотя бы одно уточнение/ограничение/термин.

Сценарии: «Настройка KMP-проекта под Android и iOS» и «Сетевой слой на Ktor + корутины».
