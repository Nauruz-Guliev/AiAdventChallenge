# День 3: Разные способы рассуждения

Проект сравнивает четыре способа решения **одной и той же логической задачи** через DeepSeek API:

1. прямой ответ без дополнительных инструкций;
2. ответ с инструкцией «решай пошагово»;
3. сначала модель создаёт промпт для решения, затем этот промпт используется второй моделью;
4. группа экспертов: аналитик, инженер и критик, после чего координатор сверяет их выводы.

## Почему задача подходит для сравнения

У задачи единственный проверяемый ответ. Шесть человек нужно расставить с понедельника по субботу:

- Глеб выступает в субботу;
- Борис выступает ровно за два места до Глеба;
- Дина выступает непосредственно перед Верой;
- Дина выступает раньше Егора;
- Егор выступает раньше Алины;
- Алина не выступает в понедельник и субботу.

Эталонный порядок: **Дина, Вера, Егор, Борис, Алина, Глеб**.

Приложение не оценивает ответ по субъективному впечатлению. Backend извлекает финальную строку `Итоговый порядок: ...` и сравнивает каждую из шести позиций с эталоном. Дополнительно интерфейс показывает объяснение, токены, reasoning-токены, время ответа и `finish_reason`.

## Вызовы API

Один запуск делает пять вызовов. Интерфейс сразу показывает точный JSON payload каждого вызова и обновляет состояние через polling, поэтому длинный reasoning-запрос не выглядит зависшим:

- один для прямого ответа;
- один с пошаговой инструкцией;
- один для группы экспертов;
- один для конструктора промпта;
- один решающий вызов с созданным промптом.

Все вызовы используют одну модель `deepseek-v4-pro`, температуру `0.2` и одну исходную задачу. Поэтому сравнение изолирует именно способ инструкции.

## Запуск

```bash
npm install
cp .env.example .env
npm start
```

Откройте http://localhost:3003.

В `.env` укажите API-ключ. Файл `.env` игнорируется Git и никогда не должен публиковаться.
