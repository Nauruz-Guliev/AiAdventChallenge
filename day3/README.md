# День 3: Разные способы рассуждения

Проект сравнивает четыре способа решения одной задачи про четыре двери и затем отправляет все ответы отдельным запросом в верификатор.

## Задача

В тёмной комнате есть четыре запертые двери, три из них ведут в стену, одна — на улицу. Есть ключ и свеча. Открыть можно только одну дверь. Нужно понять, какую выбрать, не тратя единственную попытку.

Эталонный принцип: подносить свечу по очереди к щелям или замочным скважинам, наблюдать за пламенем и выбрать дверь, у которой колебание пламени показывает поток воздуха с улицы. Дверь открывается только после проверки.

## Четыре способа

1. **Прямой ответ** — модель получает только исходную задачу.
2. **Пошаговое решение** — к задаче добавляется инструкция «решай пошагово».
3. **Сгенерированный промпт** — один вызов сначала проектирует промпт для решения, второй использует его.
4. **Группа экспертов** — аналитик, инженер и критик предлагают решения, а координатор их сверяет.

После этих способов шестой запрос отправляется отдельному **верификатору ответов**. Он получает эталонный принцип и все четыре результата, после чего возвращает JSON с оценкой каждого ответа и причиной.

## Этапы интерфейса

1. Постановка задачи.
2. Четыре параллельных способа рассуждения.
3. Отдельная проверка ответов.
4. Сводное сравнение.

Журнал API-вызовов показывает все шесть payload бок о бок: модель, сообщения, temperature, max_tokens и текущий статус. Долгие reasoning-запросы не блокируют интерфейс: frontend получает `runId` и опрашивает статус запуска.

## Критерии сравнения

- решение предлагает проверять двери свечой до открытия;
- ответ связывает колебание пламени с потоком воздуха;
- найденная дверь ведёт наружу;
- в ответе нет опасного совета открывать двери наугад;
- токены, reasoning-токены, `finish_reason` и время каждого вызова.

## Запуск

```bash
npm install
cp .env.example .env
npm start
```

Откройте http://localhost:3003.
