# День 11. Модель памяти ассистента — дизайн

Дата: 2026-09-19. Статус: утверждён пользователем (дизайн целиком, «утверждаем дизайн»).
База: `day10` (стратегии контекста). `day6`–`day10` не изменяются.

## Постановка (из задания дня 11)

Описать и реализовать модель памяти ассистента. Минимум 3 типа: краткосрочная
(текущий диалог), рабочая (данные текущей задачи), долговременная (профиль,
решения, знания). Требования: разные типы хранятся отдельно; явный выбор того,
что и куда сохраняется. Проверить: какие данные попадают в каждый слой и как это
влияет на ответы ассистента.

## Ключевые решения (итог прожарки и вопросов)

1. **Фундамент — новый `day11/` из скелета day10**; ветки, стратегии
   (sliding/facts), режимы и compare-раннер удаляются. Фокус — три слоя памяти.
2. **Три слоя = три раздельных хранилища** (прямое требование ТЗ): краткосрочная и
   рабочая в `chats/<id>.json`, долговременная в глобальном `long_term.json`,
   кандидаты в `candidates.json`.
3. **Рабочая память — структурированная карточка задачи** (`goal`, `constraints[]`,
   `decisions[]`, `status`), изменяемая (перезапись, а не append), с жизненным
   циклом `active→done`. Пишется вручную, не моделью.
4. **Долговременная — категории из ТЗ**: `profile`, `decisions`, `knowledge`;
   глобальна, переживает чаты и перезапуски.
5. **Политика записи — гибрид**: модель предлагает кандидатов после ответа →
   пользователь подтверждает/отклоняет в UI. Плюс ручная команда `запомни: ...`
   пишет сразу, минуя гейт (обход пропусков экстрактора).
6. **Проверка — ручной ритуал** в README (без автодемо); панель памяти в UI
   оставлена минимальной (просмотр + правка карточки + подтверждение кандидатов).
7. **Явное разделение в промпте**: три подписанных блока (долговременная / рабочая /
   история), чтобы влияние слоёв было наблюдаемо и в ответах, и в токенах.

## 0. Скаффолдинг

`day11` копируется из `day10`, затем удаляются: `application/context_strategy.py`,
`application/compare.py`, сущности `Branch`/`facts`/режимы, связанные API и UI
(`ModeSelector`, `FactsPanel`, табы веток, `ComparePanel`), тесты веток/режимов/
сравнения. Остаются: чаты, поток сообщений, JSON-репозиторий, подсчёт токенов и
бюджет дня 8, `usage`-чипы.

## 1. Модель данных

```python
MemoryCandidate: id, text, category: profile|decisions|knowledge,
                 source_chat_id, source_message_id, status: pending|approved|rejected
WorkingMemory:   goal: str, constraints: list[str], decisions: list[str], status: active|done
LongTermEntry:   id, text, source_chat_id, created_at
LongTermMemory:  profile: list[LongTermEntry], decisions: list[LongTermEntry],
                 knowledge: list[LongTermEntry]
Chat:            id, title, created_at, updated_at, messages: list[ChatMessage],
                 working_memory: WorkingMemory
```

- Рабочая память — поле чата (одна задача на чат), изменяемая; правка через API/UI.
- Долговременная — один глобальный документ; `LongTermEntry.id` (UUID) для удаления.
- Кандидаты — глобальный список с привязкой к чату-источнику.
- `working_memory.status == done`: карточка не инжектится в промпт, но хранится
  (архив). «Завершить задачу» ставит `done`; «Новая задача» очищает карточку.

## 2. Раздельное хранилище

- `data/chats/<id>.json` — краткосрочная (messages) + рабочая (working_memory);
- `data/long_term.json` — долговременная (глобальная);
- `data/candidates.json` — очередь кандидатов.

`JsonMemoryRepository`: CRUD чатов (как в day10), `get/update_long_term`,
`add/approve/reject_candidate`, `delete_entry`. Долговременная читается при старте
любого чата — привязки к чату нет.

## 3. Сборка промпта (`app/application/memory.py`, чистые функции)

```
[system]
## Долговременная память (глобальная)
- profile: ...
- decisions: ...
- knowledge: ...
## Рабочая память (текущая задача)        # пропускается, если status=done или карточка пуста
Цель: ...
Ограничения: ...
Решения: ...
## История диалога
<сообщения краткосрочной памяти>
```

- `build_long_term_block(lt)`, `build_working_block(wm)`, `build_prompt(chat, long_term)`
  — чистые, тестируемые.
- Блок долговременной не добавляется, если все категории пусты.
- Капы: `LONG_TERM_MAX_PER_CATEGORY=50` (защита от стены контекста),
  `LONG_TERM_MAX_ITEM_CHARS=500`.

## 4. Поток запроса (`agent.run(chat_id, text)`)

1. user message → краткосрочная;
2. сборка промпта из трёх слоёв;
3. пре-чек бюджета (день 8, `CONTEXT_LIMIT_TOKENS=8000`) по собранному запросу →
   413 при переполнении;
4. основной LLM-вызов → ответ;
5. assistant message → краткосрочная;
6. **после ответа** — LLM-вызов поиска кандидатов (вход: сообщение пользователя +
   ответ + текущая долговременная; выход: JSON-массив `{text, category}`);
   tolerant-парсер (семантика дня 9/10); кандидаты → `candidates.json`
   (`status=pending`). Стоимость — в `usage.memory_candidates`. Шаг пропускается,
   если `CANDIDATES_ENABLED=false`.

Исключение: сообщение с командой `запомни:` (см. §5) не порождает кандидатов.

## 5. Политика записи

- **Гибрид**: кандидаты из §4 показываются в UI «💾 Запомнить?» → `approve` пишет
  `LongTermEntry` в нужную категорию, `reject` помечает статус. Отклонённые в UI не
  показываются, но хранятся (для отладки) и чистятся
  `DELETE /api/candidates?status=rejected`.
- **Ручная команда**: `запомни: <текст>` (или `запомни, что <текст>`) распознаётся в
  начале сообщения; текст классифицируется тем же промптом кандидата (один вызов),
  fallback — `knowledge`; запись в долговременную **сразу**.
- **Дубликаты**: при approve точное совпадение `text` в целевой категории → 409
  (кандидат остаётся `pending`), без записи.

## 6. API

- `POST /api/chats/{id}/messages {message}` → `{answer, usage}`;
- `GET /api/chats` · `GET /api/chats/{id}` · `POST /api/chats` · `DELETE /api/chats/{id}` ·
  `DELETE /api/chats/{id}/messages` (очистить краткосрочную историю, рабочая память
  сохраняется);
- `GET /api/chats/{id}/working-memory` ·
  `PUT /api/chats/{id}/working-memory {goal, constraints, decisions, status}`;
- `POST /api/chats/{id}/working-memory/complete` (status=done) ·
  `POST /api/chats/{id}/working-memory/reset` (очистить);
- `GET /api/long-term` · `PUT /api/long-term {profile, decisions, knowledge}` ·
  `DELETE /api/long-term/{category}/{entry_id}`;
- `GET /api/candidates?status=pending` · `POST /api/candidates/{id}/approve` ·
  `POST /api/candidates/{id}/reject` · `DELETE /api/candidates?status=rejected`.

## 7. UI

- Сайдбар чатов + лента (скелет day10), чипы токенов/бюджета (day8).
- **Панель памяти**, три блока:
  - *Краткосрочная*: счётчик сообщений + кнопка «очистить историю»;
  - *Рабочая*: форма карточки (goal/constraints/decisions/status) с сохранением,
    кнопки «Завершить задачу» / «Новая задача»;
  - *Долговременная*: три категории, каждая запись с 🗑; кнопка «+ добавить».
- Блок «💾 Запомнить?» с pending-кандидатами: текст + выбор категории + ✅/✕.
- Чип под ответом: `память: долг. N · рабоч. M · истор. K` (токены по слоям).

## 8. Конфигурация

- `.env.example`: `LONG_TERM_MAX_PER_CATEGORY=50`, `LONG_TERM_MAX_ITEM_CHARS=500`,
  `CANDIDATES_ENABLED=true` + day8-лимиты.
- Порты те же (8000/5173); README просит сначала остановить day10.

## 9. Проверка — ручной ритуал (README)

1. Чат А: «кстати, я аллергик — арахис нельзя» → «Запомнить?» → ✅ knowledge.
2. **Новый чат Б**: «что ты обо мне знаешь?» → отвечает из долговременной (чат Б
   истории А не видел). Главное доказательство разделения и глобальности.
3. Рабочая: карточка «бюджет 500» → правка на «900» → «какой бюджет?» → 900
   (перезапись, а не append).
4. Удалить аллергию из долговременной → новый чат В снова не знает (источник —
   именно `long_term.json`).
5. Краткосрочная: счётчик растёт; модель ссылается на недавние сообщения;
   «очистить историю» → диалог забыт, долговременная помнится.
6. `запомни: я предпочитаю тёмную тему` → сразу в долговременной, без кандидата.

## Обработка ошибок

- битый JSON кандидатов/долговременной → старые данные целы, предупреждение в
  ответе (семантика дня 9/10);
- approve несуществующего кандидата → 404; повторный approve → 409;
- `PUT /api/long-term` с числом записей > капа → 400;
- переполнение `CONTEXT_LIMIT_TOKENS` → 413 дня 8 с подсказкой «сократите
  долговременную/рабочую»;
- пустой текст команды `запомни:` → 400.
