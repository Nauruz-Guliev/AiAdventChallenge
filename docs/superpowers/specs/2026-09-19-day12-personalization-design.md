# День 12. Персонализация ассистента — дизайн

Дата: 2026-09-19. Статус: утверждён пользователем («дизайн утверждаем, можно приступить к реализации»).
База: `day11` (модель памяти). `day6`–`day11` не изменяются.

## Постановка (из задания дня 12)

Добавить персонализацию поверх модели памяти:

- создать профиль пользователя;
- описать предпочтения (стиль, формат, ограничения);
- подключить профиль к каждому запросу.

Проверить:

- ответы для разных профилей;
- что ассистент учитывает профиль автоматически.

Результат: персонализированный агент, адаптированный под пользователя.

## Ключевые решения (итог вопросов)

1. **Основа — новый `day12/` копией `day11`**; `day11` и ранее не меняются. Память
   дня 11 (три слоя, кандидаты, `запомни:`) сохраняется полностью.
2. **Профиль структурированный**: личность (имя, роль, язык) + предпочтения
   (тон, объём, формат, список ограничений).
3. **Несколько профилей с пресетами и переключателем**: четыре пресета, активный
   переключается одним кликом — так проверяются «ответы для разных профилей».
4. **Только ручное редактирование профиля** (без авто-обучения из диалога).
5. **Подход A — отдельный блок промпта** `## Профиль пользователя`, вставляется
   первым, до долговременной памяти. Профиль хранится отдельно
   (`data/profiles.json`), а не внутри долговременной памяти.
6. **Разграничение**: профиль = *как отвечать* (тон, формат, ограничения, личность),
   долговременная `profile` = *что известно* (факты из диалога). Профиль идёт первым
   и задаёт стиль; конфликты автоматически не разрешаются (как в day11).

## 0. Скаффолдинг

`day12` копируется из `day11` (backend + frontend, без `.venv`/`node_modules`).
Порты те же (8000/5173); README просит сначала остановить day11. Скелет, память,
кандидаты, рабочая карточка и бюджет дня 8 не трогаются.

## 1. Модель данных

```python
UserProfile:
    id: str
    title: str                         # метка профиля в переключателе («Деловой»)
    name: str                          # имя пользователя
    role: str
    language: str                      # язык ответа, по умолчанию "ru"
    tone: Literal["formal", "friendly", "neutral"]
    length: Literal["short", "medium", "detailed"]
    structure: Literal["prose", "bullets", "markdown"]
    constraints: list[str]

ProfileStore:                          # документ data/profiles.json
    version: int
    active_id: str
    profiles: list[UserProfile]
```

`title` отделяет название профиля от имени пользователя: пресет «Деловой» имеет
`title="Деловой"`, а `name` остаётся пустым, пока пользователь не впишет себя.

- Профиль — отдельная сущность и отдельный файл; к чату не привязан (глобальный).
- `active_id` указывает, какой профиль подключается к запросам.
- Пустой профиль (нет предпочтений, нет имени/роли) не даёт блока в промпте.

### Пресеты (создаются при первом запуске, если `profiles.json` отсутствует)

| пресет (title) | tone | length | structure | constraints |
| --- | --- | --- | --- | --- |
| Нейтральный (без персонализации) | neutral | medium | prose | — |
| Деловой | formal | medium | markdown | без эмодзи; без воды |
| Коротко и по делу | neutral | short | bullets | без вступлений и итогов; не больше трёх пунктов |
| Наставник | friendly | detailed | markdown | объясняй термины простыми словами; приводи пример |

Активный по умолчанию — «Деловой».

## 2. Хранилище (`app/infrastructure/json_profile_repository.py`)

- `get_store()` / `get_active()` / `list_profiles()`;
- `create(profile)` / `create_from_preset(key)` / `update(id, fields)` /
  `delete(id)` / `activate(id)`;
- отдельный `asyncio.Lock` и атомарная запись (как `long_term.json`);
- при `delete` активного профиля — активным становится первый оставшийся;
- удаление последнего оставшегося профиля запрещено → 400;
- битый JSON → отдаём пустое хранилище с пресетами, старый файл цел
  (семантика дня 9/10).

  Профиль: Деловой
  Имя: Айдос; Роль: разработчик
  Отвечай на языке: русский

- Пропуск: `build_profile_block` → `None`, если профиль пуст (нет ни личности, ни

  `system` → **профиль** → долговременная → рабочая → история.
- `build_memory_trace(chat, long_term, profile)` добавляет ключ `profile` с полями
  `{name, role, language, tone, length, structure, constraints}` — для блока
  «Что учтено в ответе» (или `None`, если блок не добавлен).

## 4. Поток запроса (`agent.run`)

1. загрузка чата, долговременной и **активного профиля**;
2. сборка промпта из четырёх блоков (профиль первым);
3. пре-чек бюджета дня 8 по собранному запросу;
4. основной LLM-вызов → ответ;
5. assistant-сообщение → краткосрочная;
6. поиск кандидатов долговременной — без изменений (профиль вручную не является
   кандидатом);
7. `usage.memory` получает `profile_tokens` (токены блока профиля).

## 5. API

- `GET /api/profiles` → `{active_id, profiles}`;
- `GET /api/profiles/presets` → список шаблонов с `key`, `label`, полями;
- `POST /api/profiles` `{name, role, language, tone, length, structure, constraints}`;
- `POST /api/profiles/from-preset` `{key}`;
- `PUT /api/profiles/{id}` — частичное обновление полей;
- `DELETE /api/profiles/{id}` — 400, если профиль последний;
- `POST /api/profiles/{id}/activate` — сделать активным;
- `GET /api/profile` → активный профиль (удобство для шапки UI).

Валидация: `tone`/`length`/`structure` только из перечня; `constraints` ≤
`PROFILE_MAX_CONSTRAINTS`, каждый ≤ `PROFILE_MAX_ITEM_CHARS`; иначе 400/422.

## 6. UI

- **Переключатель профиля** — чипы профилей в панели «Профиль» (левая колонка,
  над «Разрезом памяти»): активный выделен, клик переключает.
- **Панель «Профиль»**: форма (имя, роль, язык, сегменты тон/объём/формат, список
  ограничений с добавлением/удалением), кнопки «Создать из пресета»,
  «Дублировать», «Удалить».
- **«Что учтено в ответе»**: новая строка **«Профиль»** рядом с памятью.
- Мета-чип ответа: токены профиля отдельным числом.
- Дизайн — тёмный монохром дня 11, без градиентов, цвет только по смыслу. Для
  профиля вводится отдельный смысловой акцент (точный оттенок финализируется на
  этапе вёрстки через скилл `frontend-design`).
- Новый компонент `ProfilePanel.jsx` (переключатель + форма + пресеты),
  монтируется первым блоком в «Разрез памяти».

## 8. Проверка — ручной ритуал (README)

1. Профиль **«Нейтральный»**, вопрос «Объясни, что такое API» → базовый ответ.
2. **«Коротко и по делу»**, тот же вопрос → короткие пункты без вступлений.
3. **«Наставник»** → дружелюбно, подробно, с примером.
4. **«Деловой»** → сухо, markdown, без эмодзи.
   → один и тот же вопрос при разных профилях даёт разный тон/формат — профиль
   реально подключён к каждому запросу.
5. **Новый чат** — профиль сохраняется (глобальный, не привязан к чату).
6. **«Что учтено в ответе»** → строка «Профиль» присутствует, хотя в сообщении
   профиль не упоминался — учёт автоматический.
7. Добавить ограничение **«без эмодзи»** → ответ без эмодзи.
8. Переключить на **«Нейтральный»** → влияние исчезает (контроль).
