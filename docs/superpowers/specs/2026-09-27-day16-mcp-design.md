# Day 16 — Подключение MCP

## Цель

Создать минимальный работающий пример подключения к MCP (Model Context
Protocol): демо-сервер с инструментами и клиент, который устанавливает
соединение и получает список доступных инструментов. Результат — код, который
подключается к MCP и выводит список инструментов, плюс автотест, доказывающий,
что соединение устанавливается и список возвращается корректно.

## Не-цели (YAGNI)

- НЕ интегрируем инструменты в LLM-агента (это будущие дни).
- НЕ копируем бэкенд/фронтенд day15 — день чисто про MCP.
- НЕ подключаемся к внешним MCP-серверам (Atlassian/Jira/Bitbucket).
- Вызов инструмента (`call_tool`) делаем только как опциональную демонстрацию
  в клиенте, но не как часть обязательного минимума.

## Архитектура

Один маленький Python-пакет внутри `day16/` (собственное venv):

```
day16/
  README.md          # что такое MCP, как запустить, разбор кода построчно
  LESSON.md          # отдельный урок: как MCP устроен и как настроить самому
  requirements.txt   # mcp (официальный SDK)
  server.py          # демо MCP-сервер (FastMCP) с тремя инструментами
  client.py          # клиент: stdio-подключение + initialize + list_tools
  test_mcp.py        # автотест: соединение поднимается, список возвращается
  video-script.html  # сценарий видео (в .gitignore, как в прошлых днях)
  .gitignore         # .venv/, __pycache__/, video-script.html и т.п.
```

### server.py — демо-сервер

Используем высокоуровневый `FastMCP` из пакета `mcp`. Три инструмента через
декоратор `@mcp.tool()`:

- `add(a: int, b: int) -> int` — сложение двух чисел.
- `echo(text: str) -> str` — повтор строки.
- `today() -> str` — сегодняшняя дата (ISO).

Инструменты выбраны разные по сигнатуре, чтобы вывод `list_tools()` был
наглядным: у каждого видно имя, описание и входную JSON-схему (`inputSchema`).

Запуск сервера для отладки: `python server.py` (FastMCP поднимает stdio-режим).

### client.py — клиент

Асинхронный клиент на `mcp.client.stdio.stdio_client` + `ClientSession`:

1. `StdioServerParameters(command=..., args=["server.py"], cwd=...)` — параметры
   запуска сервера как подпроцесса.
2. `stdio_client(...)` открывает JSON-RPC канал через stdin/stdout.
3. `await session.initialize()` — рукопожатие (обмен capabilities).
4. `result = await session.list_tools()` — запрос `tools/list`.
5. Выводим каждый инструмент: имя, описание, входную схему.

Это покрывает оба требования задания: «устанавливает MCP-соединение» и
«получает список доступных инструментов».

Опционально: флаг `--call add 2 3` для демонстрации реального вызова
инструмента через `session.call_tool(...)` (учебно, не входит в минимум).

### test_mcp.py — проверка

pytest-тест (asyncio), который:

- сам поднимает сервер через `stdio_client` (команда — `sys.executable`,
  аргументы — путь к `server.py`),
- делает `initialize()`,
- вызывает `list_tools()`,
- проверяет, что вернулись ровно три инструмента с именами
  `add`, `echo`, `today`, и что у `add` есть `inputSchema`.

Тест доказывает оба пункта «Проверьте» из задания автоматически.

## Зависимости

- Python 3.11 (как в остальном проекте).
- `mcp` — официальный Python SDK Model Context Protocol.
- `pytest`, `pytest-asyncio` (или asyncio_mode из pyproject, как в day15).

Собственное venv в `day16/.venv`, `requirements.txt` со списком пакетов.

## Обучение (отдельная задача пользователя)

Помимо кода создаём отдельный урок `day16/LESSON.md`, который объясняет:

- что такое MCP и зачем он нужен (проблема «N интеграций по-разному»),
- роли: сервер / клиент / транспорт, понятие tool и inputSchema,
- как устроен обмен по JSON-RPC 2.0 (запрос `tools/list` → ответ),
- разбор транспорта stdio против SSE/HTTP,
- как самому написать сервер (FastMCP) и клиента,
- как настроить MCP-сервер в сторонних клиентах (на будущее — как это выглядит
  в конфигах, без привязки к конкретному продукту).

## Проверка результата

1. `pytest -q` в `day16/` — все тесты зелёные.
2. `python client.py` — в консоль выводится список из трёх инструментов.
3. `python client.py --call add 2 3` — выводит `5` (опционально).
4. `python server.py` запускается в stdio-режиме без ошибок.
