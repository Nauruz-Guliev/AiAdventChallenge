# День 10. Управление контекстом: стратегии (без summary) — дизайн

Дата: 2026-09-14. Статус: утверждён пользователем (секции 1–6, «да, поехали»).
База: `day9` (rolling-summary). `day6`–`day9` не изменяются.

## Постановка (из задания дня 10)

Минимум 3 стратегии управления контекстом + переключатель между ними:
sliding window, sticky facts (KV-память), branching (ветки диалога). Прогнать один
сценарий («собираем ТЗ», 10–15 сообщений) на каждой стратегии и сравнить качество,
стабильность, расход токенов, удобство.

## Ключевые решения

1. **4-й режим `full` как базовая линия** (решение пользователя): честный ноль сравнения = поведение дня 8.
2. **Без summary** — задание явно запрещает; скользящее окно и facts заменяют свёртку дня 9 на «механических» стратегиях.
3. **Хранилище полное, отбирается сборка запроса** (философия дня 9 сохранена): sliding window ничего не удаляет из `chats.json`.
4. **Facts живут в ветке**, ветки — структура диалога, режимы — способ сборки. Orthogonal.
5. **Compare-раннер** — автоматический прогон скриптованного ТЗ-сценария во всех 4 режимах с детерминированным скорингом.

## 0. Скаффолдинг

`day10` копируется из `day9`, после чего **слой сжатия удаляется**: `application/compression.py`, `CompressionInfo`, `Chat.summary/summary_covers` (и их персист), `compress` в запросе, тумблер/чип свёртки в UI, связанные тесты. Философия «сборка ≠ хранилище» и вся day8-бюджетная часть остаются.

## 1. Модель данных

```python
Branch: id: UUID, name: str, fork_at: int | None, messages: list[ChatMessage], facts: dict[str, str]
Chat:   id, title, created_at, updated_at,
        branches: list[Branch], active_branch_id: UUID
```

- `chats.json`: legacy плоский `messages` при загрузке оборачивается в ветку «main» (`fork_at=None`), `facts={}`; при сохранении пишется новая схема. Тест round-trip + legacy.
- API-ответ `GET /api/chats/{id}`: `branches: [{id, name, fork_at, messages}]`, `active_branch_id`; лента сообщений UI берётся из активной ветки.
- `append_exchange(chat_id, user_text, assistant_text, usage, branch_id=active)`; `save_facts(chat_id, branch_id, facts)`.

## 2. Режимы сборки (`app/application/context_strategy.py`, чистые функции)

```python
MODES = ("full", "sliding", "facts", "branching")

assemble(mode, branch, new_text) -> list[ChatMessage]  # только history-часть, без system
```

- `full`: вся история ветки (стена 413 дня 8 остаётся единственной живой стеной);
- `sliding`: последние `SLIDING_WINDOW_MESSAGES=10`;
- `facts`: факты-блок (см. §3) + последние 10 + новое сообщение (по тексту задания);
- `branching`: вся история активной ветки (ветвление = структура, не assembly).

Пре-чек бюджета (`CONTEXT_LIMIT_TOKENS=8000`) — по **собираемому** запросу; в sliding/facts почти недостижим, что и демонстрируется. Поле запроса `mode` заменяет `compress` (day9-свёртка в UI недоступна, код `compression.py` в day10 не переносится).

## 3. Sticky facts

После каждого user-сообщения в режиме `facts`:

1. LLM-вызов «обнови facts»: вход — текущие facts (JSON) + новое сообщение; выход — JSON `{key: value}` (цель, ограничения, предпочтения, решения, договорённости, цифры); cap `FACTS_MAX_ITEMS=20`;
2. сохранение до основного вызова (страховка из дня 9: свёртка/факты переживают падение API);
3. парсинг tolerant (regex-извлечение JSON-объекта); при мусоре — старые facts целы, событие в лог;
4. блок фактов в запросе: одна system-реплика «Известные факты о задаче:\n- key: value…»;
5. стоимость экстракции — в `usage.fact_update` (токены, $), видна в чипе.

Ручное управление: панель facts в UI (редактировать/удалить/добавить) → `PATCH /api/chats/{id}/facts {branch_id, facts}`.

## 4. Branching

- `POST /api/chats/{id}/branches {after_message_index, name}` — копия истории активной ветки до индекса включительно; новая ветка активна; `facts` наследуются на момент fork;
- `PATCH /api/chats/{id}/active-branch {branch_id}`; `DELETE .../branches/{branch_id}` (409 на последнюю);
- UI (в режиме `branching`): кнопка «🌿 Ветвиться отсюда» под каждой ассистентской репликой, табы веток над лентой с индикатором активной;
- демо-сценарий дня: checkpoint после 6-го сообщения → ветки «скорость» / «надёжность» → независимые продолжения → переключение табов.

## 5. Compare-раннер

- `POST /api/compare` → сервис `application/compare.py`:
  - скрипт сценария «собираем ТЗ» — 10 сообщений с **6 контрольными фактами** вшитыми в разные ходы: кодовое имя «Буревестник», бюджет «1200 человеко-дней», срок «до 15 декабря», запрет «без внешнего облака», выбор «PostgreSQL», договорённость «отчёт по пятницам»;
  - финальный вопрос: «Собери ТЗ списком. Какое кодовое имя и бюджет?» + детерминированный substring-скоринг по финальному ответу (6/6);
  - прогон параллельно в 4 временных чата (режимы), asyncio.gather; чаты остаются в сайдбаре с префиксом `⚖`;
  - метрики на режим: выжившие факты (какие именно ✔/✘), `prompt/completion` токены, $, число вызовов (facts-экстрактор — вызовы!), время, факт 413;
  - сбой одного режима → строка с ошибкой, остальные живут (семантика day3);
  - скоринг и скрипт — чистые функции, тестируются на scripted-gateway.
- UI: кнопка «Сравнить стратегии» → прогресс-строки по режимам → таблица (rows=режимы): выживание фактов чипами, токены, $, вызовы, сек, «открыть диалог» по клику на строку.

## 6. UI и конфигурация

- Сегментированный переключатель `Режим: Полный | Окно | Факты | Ветки` (persist `localStorage['day10-mode']`, дефолт `sliding`);
- чипы под ответом: `sliding: отправлено 10 из 23` / `facts: 7 фактов + 10 сообщений, экстракция −$…`;
- панель facts видна только в режиме `facts`; табы веток — только в `branching`;
- `.env.example`: `SLIDING_WINDOW_MESSAGES=10`, `FACTS_MAX_ITEMS=20` + day8-лимиты;
- README: тот же ритуал что в секциях, фактические цифры живого прогона, раздел «честные ограничения» (sliding теряет среднее, facts теряют нюансы и стоят вызова, ветки не спасают от роста внутри ветки, compare — один сценарий не статистика).

## Обработка ошибок

- legacy-чат без `branches` → миграция при загрузке; запись всегда в новую схему;
- ветка-цель удалена/не найдена → 404; удаление последней ветки → 409; `after_message_index` вне диапазона → 400;
- битый JSON у экстрактора фактов → старые facts + предупреждение в чипе;
- 413 в `full` — сообщение дня 8/9 («включите сжатие» правится на «смените режим»).
