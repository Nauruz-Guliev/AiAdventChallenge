# День 14 — инварианты и ограничения состояния (дизайн)

Дата: 2026-09-21. База: `day13` (профиль + память + конечный автомат задачи).

## Цель

Добавить ассистенту инварианты — ограничения, которые он не имеет права
нарушать (архитектура, технические решения, стек, бизнес-правила). Требования:

- инварианты хранятся отдельно от диалога;
- ассистент явно учитывает их в рассуждениях;
- ассистент отказывается предлагать решения, которые их нарушают;
- виден результат проверки: что происходит при конфликте и как объясняется отказ.

## Решения

1. **Хранилище.** Отдельный файл `data/invariants.json`, отдельный порт
   `InvariantRepository` и инфраструктурный `JsonInvariantRepository` (по образцу
   профилей из дня 12). При первом запуске — сид из инвариантов проекта.
   Управление — из UI (CRUD-эндпоинты).

2. **Проверка конфликта — LLM-страж.** Отдельный вызов до основного ответа:
   промпт получает список инвариантов и сообщение, возвращает строгий JSON
   `{"violates": bool, "invariant_id": ..., "reason": ...}`. Сомнительное —
   не нарушение. Нет инвариантов — вызов пропускается. Сбой/невалидный JSON —
   fail-open (ответ идёт обычным путём, потраченные токены учитываются).

3. **Отказ.** Текст отказа строит бэкенд детерминированным шаблоном: какой
   инвариант (текст + категория) нарушен и почему. При отказе основная
   контент-модель не вызывается, извлечение кандидатов пропускается, этап и шаг
   задачи не меняются.

4. **Учёт в рассуждениях.** При отсутствии конфликта блок инвариантов
   добавляется в system prompt, поэтому модель явно работает в их рамках.

5. **Связь с днём 13.** Порядок обработки: пауза (route) → страж (agent) →
   обычный ответ с продвижением автомата. Отказ не создаёт и не двигает задачу.

## API

- `GET /api/invariants`, `POST /api/invariants` (`text`, `category`),
  `DELETE /api/invariants/{id}`;
- в ответе `POST /api/chats/{id}/messages` — поле `violation`:
  `{invariant_id, reason, invariant?}`.

## UI

Панель «Инварианты»: список с категориями, добавление (текст + категория),
удаление. Отказ в чате — пузырь с золотой рамкой, чипом «запрос отклонён» и
подписью с текстом нарушенного инварианта. Дизайн-язык как в днях 11–13: без
градиентов, мятный акцент профиля, золото = предупреждение.

## Тесты

- домен/хранилище: сид, добавление, удаление, ошибки, отдельный файл;
- страж: нарушение, чистота, fenced-JSON, неизвестный id, невалидный JSON,
  ошибка шлюза, пустой список;
- API: CRUD, валидация, 404;
- агент: отказ без вызова контент-модели, состояние не двигается, отказ
  сохраняется в чат, блок инвариантов в промпте, пропуск стража без инвариантов.

## Вне рамок (YAGNI)

Эмбеддинги и семантический поиск, ключевые слова на инвариант, история правок,
мультипользовательность, отдельный этап `blocked` в автомате.
