День 30 — приватный LLM-сервис

Как локальную модель превратить в сервис: HTTP API, чат, авторизация, лимиты и стабильность под нагрузкой.

Идея

Ollama умеет отдавать модель по HTTP, но это рантайм, а не сервис: без авторизации, rate limit, лимита контекста и очереди. Поэтому наружу смотрит FastAPI-шлюз, а Ollama остаётся на localhost.

клиент ──HTTP + ключ──► шлюз:8000 ──► Ollama:11434 ──► gemma4:12b
                        ├─ авторизация
                        ├─ rate limit (token bucket)
                        ├─ лимит контекста
                        └─ очередь (семафор)

Собери сам — по шагам

1. Подними Ollama и модель: ollama pull gemma4:12b.
2. Создай venv и поставь зависимости: pip install -r requirements.txt.
3. Задай ключ: $env:API_KEYS = "my-secret-key".
4. Запусти шлюз: .\scripts\run_service.ps1 → слушает 0.0.0.0:8000.
5. Проверь сеть: .\scripts\lan_ip.ps1 и открой http://<IP>:8000/.
6. Нагрузи: python scripts\stability_test.py --requests 24 --workers 12.

Базовые ограничения

ОграничениеЗначениеОтвет при превышении
Авторизацияключ из окружения401
Rate limit30/мин, burst 10429 + Retry-After
Контекстnum_ctx 8192400
Очередь1 активный, очередь 8503 + Retry-After

Что показала проверка

Доступ по сети: /health отвечает и на localhost, и по LAN-IP.

24 запроса подряд: 46% OK, 50% 429, 4% 503, p50 ≈ 3.2 с, p95 ≈ 4.5 с — сервис не упал.

Лимиты: длинный промпт → 400, поток запросов → 429.

Почему это «приватно»

Данные не покидают дом: браузер → шлюз на этом же ПК → Ollama. Для доступа извне нужен TLS (проще всего Caddy как reverse proxy) и/или VPN, но модель и вычисления остаются у тебя.
