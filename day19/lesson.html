01Что такое композиция

Один инструмент делает одно дело. Композиция — когда несколько инструментов соединяются в цепочку, где выход одного становится входом следующего:

search→ summarize→ save_to_file

Ключ — явные контракты: каждый инструмент принимает и возвращает понятные типы (dict с известными полями). Тогда звенья стыкуются без «магии», а цепочку можно проверять по частям.

02MCP — pull-модель

Сервер не может сам «толкнуть» агенту промежуточный результат. Поэтому цепочку собирают двумя способами: агент вызывает инструменты по очереди (гибко, но зависит от LLM) либо сервер отдаёт составной инструмент, выполняющий всю цепочку внутри.

Здесь есть оба: три отдельных инструмента и составной pipeline. Второй и есть автоматическое выполнение цепочки.

03search: получение данных

Ходит в Wikipedia Search API (action=query&list=search), без ключа:

{"query": "...", "results": [{"title", "url", "snippet"}]}

Тонкость: snippet приходит с HTML (<span class="searchmatch">…</span>), его чистит _strip_html.

Ошибки: сеть/пустой ответ → SearchError → ValueError в сервере (MCP покажет ошибку, процесс не падает).

04summarize: обработка

Экстрактивная суммаризация без LLM:

  1. текст режется на предложения;
  2. считается частотность значимых слов (длина ≥ 3, без стоп-слов);
  3. предложение оценивается суммой частот, делённой на длину;
  4. топ-N возвращается в исходном порядке — так саммари читается связно.

Чистая функция: ни сети, ни файлов — поэтому легко тестируется.

05save_to_file: сохранение

Пишет контент как есть в UTF-8 и возвращает {path, bytes_written, written_at}. Каталог out/ создаётся автоматически.

Разделение обязанностей: storage только пишет; заголовок и структуру markdown собирает pipeline.

06pipeline: автоматическая цепочка

Связывает три этапа и возвращает отчёт о передаче данных:

{
  "query": "...",
  "stages": {
    "search":    {"result_count": 5, "top_titles": [...]},
    "summarize": {"sentence_count": 2, "summary_chars": 53},
    "save":      {"path": "...", "bytes_written": 487}
  },
  "output_path": "...",
  "summary": "..."
}

Именно stages доказывают корректность передачи: видно, сколько данных пришло на вход каждого этапа и что вышло наружу.

08Проверка и демо

Тесты: pytest -q → 18 офлайн-тестов.

Живьём: pipeline.run('Model Context Protocol') → отчёт + файл в day19/out/.

В opencode: «Найди в Википедии … и сохрани конспект» — одна фраза, цепочка из трёх инструментов, готовый файл.

Упражнения: добавить translate между summarize и save; ограничить число источников; сохранять сырой JSON рядом.
