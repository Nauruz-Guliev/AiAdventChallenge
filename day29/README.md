# День 29 — Оптимизация локальной LLM под RAG по KMP

Оптимизируем локальную модель под **конкретную задачу** — RAG-ответы по базе Kotlin
Multiplatform — и сравниваем **до/после** прямо в Telegram: качество, скорость и потребление
ресурсов. Плюс исправлен вывод в Telegram (markdown и таблицы теперь рисуются аккуратно).

Стек: aiogram 3 + httpx (Ollama) + openai SDK (судья DeepSeek) + sentence-transformers + psutil.
Архитектура — clean architecture; бот дня 28 доработан, лежит в отдельной папке `day29`.

## Идея

Оптимизируем только **генерацию** (retrieval не трогаем — так честнее видно вклад оптимизации):

- **параметры инференса** — `temperature`, `top_p`, `top_k`, `num_predict` (лимит длины),
  `num_ctx` (окно контекста), `repeat_penalty`;
- **квантование** — сравниваем текущий `Q4_K_M` с более точным `Q8_0`;
- **prompt-шаблон** — строгий формат ответа по контексту (кратко, со ссылками `[n]`).

## Профили (абляции)

| Профиль | num_ctx | temperature | top_p | top_k | num_predict | repeat_penalty | Промпт |
|---|---|---|---|---|---|---|---|
| `baseline` (как день 28) | 8192 | дефолт (≈1.0) | 0.95 | 64 | — | — | старый |
| `params` | 4096 | 0.2 | 0.9 | 40 | 512 | 1.1 | старый |
| `optimized` | 4096 | 0.2 | 0.9 | 40 | 512 | 1.1 | новый |

Кванты: `q4` = `gemma4:12b` (Q4_K_M) · `q8` = `gemma4:12b-it-q8_0` (Q8_0).

## Команды бота

| Команда | Что делает |
|---|---|
| `/profile` | показать активный профиль; `/profile baseline\|params\|optimized` — переключить |
| `/quant q4\|q8` | переключить квант; показать размер и память |
| `/ab` | быстрый A/B: 3 вопроса × 1 |
| `/ab full` | полный A/B: 10 вопросов × 2 (все профили × оба кванта) |
| `/eval` | локально vs облако (RAG) — как в дне 28 |
| `/status` | модель, квант, профиль, индекс, режим |
| `/rag` · `/norag` | поиск по базе вкл/выкл |
| `/think on\|off` | показывать «размышления» |
| `/new` · `/id` · `/help` | история, id, справка |

Кнопки под ответом: `⚙️ Профиль` · `🔀 Квант` · `📊 A/B` · `🧪 Оценка` · `☁️ Облако` · `🔄 RAG`.

Переключи профиль и задай один и тот же вопрос — увидишь разницу «до/после» вживую.

## Как считается A/B

Матрица **3 профиля × 2 кванта**. По каждому вопросу retrieval выполняется один раз, и один и
тот же контекст подаётся всем конфигурациям.

- **Качество** — слепой судья `deepseek-chat` (0…1 по эталону, не знает профиль и квант).
- **Скорость** — латентность (мс) и tok/s (`eval_count`/`eval_duration` Ollama).
- **Токены промпта** — `prompt_eval_count`.
- **Ресурсы** — размер модели на диске, память рантайма (`/api/ps` + RSS процесса Ollama), CPU%
  процесса Ollama, время загрузки модели.

Отчёт выводится моноширинным блоком с дельтами `optimized vs baseline` и `Q8_0 vs Q4_K_M`.

## Запуск

```powershell
cd day29/backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
ollama pull gemma4:12b-it-q8_0     # для сравнения квантов (~13 ГБ)
copy .env.example .env             # вставить TELEGRAM_BOT_TOKEN и DEEPSEEK_API_KEY
.\run_bot.ps1
```

> `pip` при корпоративном SSL: добавь `--trusted-host pypi.org --trusted-host files.pythonhosted.org`.

> Telegram блокируется сетью — укажи в `.env` `TELEGRAM_API_IP=149.154.167.220` (бот пойдёт к
> рабочему IP, сохранив SNI/сертификат; polling переподключается сам).

> ⚠️ Токен один с днём 28 — **одновременно два бота нельзя**; останови день 28 (`.stop_bot.ps1`).

## Что изменилось в выводе в Telegram

- Раньше markdown не рисовался: конвертер отдавал `<p>`/`<br>`, Telegram HTML их не поддерживает
  → `parse_mode="HTML"` падал и сообщение оставалось сырым. Теперь конвертер использует только
  поддерживаемые теги (`b/i/u/s/code/pre/a`), рендерит HTML **и во время стриминга**, а таблицы
  отчётов выводятся моноширинным `<pre>`. Тот же фикс бэкпортирован в день 28.
