# День 9: управление контекстом — сжатие истории

Самостоятельное продолжение `day8`. Старая часть диалога сворачивается в rolling-summary, последние N сообщений уходят «как есть», а тумблер в UI включает и выключает сжатие — можно сравнить качество ответов и расход токенов на одном чате.

`day6`–`day8` не изменяются.

## Что изучаем

День 8 показал стену: каждая реплика пересылает всю историю, диалог дорог и конечен. День 8 честно заморозил переполненный чат. День 9 отвечает, что с этим делают агенты:

1. полный контекст — не обязательное зло: старые сообщения можно заменить сжатой свёрткой;
2. сжатие — это **сборка запроса**, а не удаление: полная история остаётся в хранилище;
3. сжатие не бесплатно: свёртка сама стоит токенов и может терять детали.

## Механика

```env
CONTEXT_LIMIT_TOKENS=8000   # жёсткий бюджет запроса (день 8)
COMPRESS_AT_TOKENS=3000     # выше какого размера истории включается сжатие
KEEP_RECENT_MESSAGES=10     # хвост диалога, который уходит без изменений
SUMMARY_MAX_TOKENS=500      # целевая длина свёртки
```

При `compress=true` и оценке истории выше порога:

```
было:  [system] + [m1 ... m24] + [новое сообщение]
стало: [system] + [system: краткое содержание m1..m14] + [m15 ... m24] + [новое сообщение]
```

- Свёртку просит у той же модели один отдельный вызов (`app/application/compression.py`); она кэшируется в чате (`summary`, `summary_covers`) и пересобирается, только когда старая часть выросла.
- Полная история **не удаляется** — в `data/chats.json` по-прежнему все сообщения, плюс свёртка.
- Если даже сжатый запрос больше бюджета (огромный хвост) — остаётся честный `413` из дня 8.

## Измерено на живом API

Чат раздут до 12 сообщений (~9.3k токенов истории), бюджет 8000.

| шаг | режим | результат |
| --- | --- | --- |
| тот же вопрос, `compress=off` | полный контекст | `HTTP 413` — 9 423 из 8 000 (стена дня 8) |
| `compress=on`, первый ход | сжатие | запрос прошёл: `prompt_api` 324; `before/after` 9 300 → 404 (**−96%**); свёртка стоила 6 268 токенов (**$0.002024**); на вопрос «какое кодовое слово?» ответ — «изумруд-77» (память через summary) |
| следующий ход, `compress=on` | кэш+rolling | `prompt_api` 358; свёртка пересобралась (6 464 токена), т.к. граница старой части сдвинулась |
| `GET /api/chats/{id}` | хранилище | все 16 сообщений на месте, `summary_covers=4` |

Экономика: одна свёртка ~$0.002 вместо мгновенной смерти диалога; каждый последующий ход платит ~400 входных токенов вместо ~9 300.

## Сравнение качества (тумблер)

1. Надуй диалог кнопкой «Симулировать длинный диалог» или вставь несколько простыней текста.
2. `Сжатие истории` **выкл** → задай вопрос про деталь из первого сообщения → либо ответ из полной истории, либо 413.
3. Включи сжатие → тот же вопрос: смотри чип `было X → стало Y (−Z%)` и проверяй, что модель помнит из начала: имена, числа, кодовые слова summary сохраняет, нюансы формулировок — нет.
4. Задай вопрос про «середину» — старые детали могут уже не вернуться: это и есть цена компрессии.

## Честные ограничения

- **Пересуммаризация на каждой границе**: пока сжатие активно, каждый новый exchange сдвигает старую часть → свёртка пересобирается каждый ход. В проде троттлят (пачки по M сообщений) — здесь это упражнение на читателя.
- **Потери**: summary хранит факты/решения/имена, теряет дословность и длинные рассуждения.
- **Дрейф**: rolling-summary обновляется сам из себя — на очень длинных диалогах ошибки кумулируются.
- Автоочистка, сегментные свёртки, векторный поиск — «дале».

## Запуск backend

```bash
cd day9/backend
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

Создай `day9/backend/.env` по образцу `.env.example` (ключ DeepSeek + четыре лимита выше).

```bash
uvicorn app.main:app --reload
```

## Запуск frontend

```bash
cd day9/frontend
npm install
npm run dev
```

Открой `http://localhost:5173`. Если `day8` запущен на тех же портах — сначала останови его.

## API

- `POST /api/chats/{id}/messages` — тело `{message, compress}` (по умолчанию `true`); в ответе `usage.compression: {applied, before_tokens, after_tokens, saved_tokens, saved_percent, summarization_tokens, summarization_cost_usd} | null`;
- `GET /api/chats/{id}` — плюс `summary`, `summary_covers`;
- `413` — когда не спасло даже сжатие; текст теперь предлагает включить сжатие.

## Структура

- `app/application/compression.py` — чистые функции: `split_history`, сборка суммаризационного запроса и summary-system-сообщения;
- `app/application/agent.py` — `run(chat_id, text, compress=True)`: `_ensure_summary` + предчек бюджета уже сжатого контекста;
- `app/domain/models.py` — `Chat.summary/summary_covers`, `CompressionInfo`, поля `UsageConfig`;
- `app/infrastructure/json_chat_repository.py` — `save_summary`, round-trip полей;
- `frontend/src/App.jsx`, `components/ChatPanel.jsx` — тумблер (`localStorage['day9-compress']`) и чип экономии под ответом.
